# Fleet Controller Source Index

`fleet-controller` owns the HTTP/WebSocket controller interface and its adapters to application and storage contracts.

| Path | Kind | Responsibility | Boundary / Side effects |
| --- | --- | --- | --- |
| `catalog_fetch.rs` | Infrastructure | Validates a public Git authority, pins each libgit2 HTTPS tunnel to policy-checked DNS addresses through a controller-local CONNECT proxy, and decodes bounded immutable Git tree blobs into validated catalog fetch results while ignoring unrelated YAML and rejecting invalid declared Fleet documents, links, submodules, or oversized catalog documents. | Resolves and reads Git through libgit2; never accepts credentials or invokes a shell. The proxy rejects other CONNECT authorities and closes stalled tunnels at the hard deadline or cancellation. |
| `lib.rs` | Interface library | Serves controller APIs and authenticated agent sessions, validates inbound drift correlation, renders remediation lifecycle from persisted assignment/evidence rows, rejects deprecated manual lifecycle mutations, joins persisted verification result/evidence for origin-only remediation resolution, maps task lifecycle events to application persistence ports, and exposes authorized durable catalog reads plus owner/admin source registration and bounded asynchronous sync-start requests; owns the bounded catalog-sync worker, performs bounded pre-listener verification recovery, and dispatches committed remediation verification Jobs. | Performs network, storage, signing, audit, and session-registry coordination through explicit controller dependencies; catalog fetch runs in the blocking pool after releasing the store lock and shares timeout/shutdown cancellation with the pinned HTTPS transport. |
